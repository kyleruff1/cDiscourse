## Goal (one paragraph)

A11Y-693 shipped one shared reduce-motion primitive — `useReduceMotion(reduceMotionOverride?)` at `src/features/preferences/useReduceMotion.ts` — and gave it exactly ONE component consumer, `DisagreementPointsRail`. The other `Animated.timing` sites in the room still hand-roll the reduce-motion read (four of them inline the raw `AccessibilityInfo.isReduceMotionEnabled()` + `addEventListener('reduceMotionChanged')` effect verbatim; one reads only a `reduceMotion` prop with no OS self-read). A11Y-693 explicitly deferred consolidating them ("Migrating the other ~6 inline reduce-motion copies … a separate dedupe card", `docs/designs/A11Y-693-ASP.md` §"Out of scope"), and UX-PR-E's F-26/MOTION section names **P2-12** as that card ("Consumers (Wave-2 P2-12) thread the existing `useReduceMotion` hook … through the uncovered Animated sites", `docs/designs/UX-PR-E.md`:155-159). This card threads the existing hook through the five listed sites so every `Animated.timing` in the room consults ONE reduce-motion source. The doctrine that shapes it is `accessibility-targets` §"Reduce motion" (non-essential animation degrades to static when the OS asks) — but the load-bearing constraint here is **byte-identical motion-on behavior**: the hook returns the identical value the inline code produced and honors the identical `reduceMotionOverride` prop, so when reduce-motion is OFF nothing about the animation changes; when it is ON the surface reaches its final visual state instantly, exactly as today. No new hook, no re-inlined `AccessibilityInfo` logic, no new animation, no duration change, no motion redesign.

### Precision note on the card premise (important — read before implementing)

The card says these sites "don't yet honor reduce-motion." That is imprecise, and the imprecision matters for verification. The accurate statement is: **these sites don't yet consume the shared hook.** All five already gate their tween:

- `ArgumentComposerDock`, `ArgumentSideActionRail`, `Popout`, `OpenIssuesRail` — **already honor OS reduce-motion** via an inline `AccessibilityInfo` read + the `reduceMotionOverride` prop. For these four the swap is a **pure dedupe consolidation** (behavior-identical in every case).
- `TimelineMiniMap` — honors reduce-motion **only** via a passed `reduceMotion` prop; it has **no OS self-read**. For it the swap is dedupe **plus** a latent OS-fallback coverage gain (see §Per-site plan). Both of its live mounts already pass the prop, so even that is a no-op in the shipped app today.

This distinction is what makes "motion-on byte-identical" provable: `useReduceMotion(x)` returns `typeof x === 'boolean' ? x : os`, which is exactly the inline expression each of the four already computes, and exactly the fallback the mini-map lacks.

## Data model

**No new data model. No persisted state. No migration. No Edge Function. No RLS. No new prop, type, or export.** This is a source-consolidation + reduce-motion-coverage card. The only new symbol referenced is the already-shipped `useReduceMotion` import in five files.

The hook's contract (unchanged, `src/features/preferences/useReduceMotion.ts`):

```ts
export function useReduceMotion(reduceMotionOverride?: boolean): boolean;
//   boolean override wins in BOTH directions (test seam + parent-threaded value);
//   else the live OS AccessibilityInfo value, subscribed to reduceMotionChanged;
//   default-safe false until the async read resolves, false if the API rejects /
//   is unavailable (web shim / jest). Pure hook: no Supabase, no fetch, no network.
```

## The canonical pattern (the exact template all sites must mirror)

Read in full from `DisagreementPointsRail.tsx` (the shipped, covered consumer). It is the ONLY authorized shape:

**1. Import (relative path depends on the file's directory):**
```ts
import { useReduceMotion } from '../preferences/useReduceMotion';   // mediator/, arguments/
```

**2. Derive ONE value near the top of the component (DisagreementPointsRail.tsx:227-230):**
```ts
// reduce-motion read (shared useReduceMotion hook)
const effectiveReducedMotion = useReduceMotion(reduceMotionOverride);
```
The prop passed to the hook is whatever reduce-motion prop the component already exposes (`reduceMotionOverride` for four sites; `reduceMotion` for the mini-map). The hook honors the boolean override in precedence — identical to the inline `typeof reduceMotionOverride === 'boolean' ? reduceMotionOverride : prefersReducedMotion` the four sites compute today.

**3. Gate the `Animated.timing` (DisagreementPointsRail.tsx:253-269):**
```ts
const progress = useRef(new Animated.Value(expanded ? 1 : 0)).current;
useEffect(() => {
  if (effectiveReducedMotion || variant === 'side' || presentation === 'pane') {
    progress.setValue(expanded ? 1 : 0);   // SNAP to the FINAL value — no tween
    return;
  }
  const animation = Animated.timing(progress, { toValue: expanded ? 1 : 0, duration: 160, useNativeDriver: true });
  animation.start();
  return () => animation.stop();
}, [expanded, effectiveReducedMotion, variant, presentation, progress]);
```
The reduced branch calls `progress.setValue(<final>)` and `return`s early: the `Animated.Value` jumps straight to its terminal value (1 = open, 0 = closed), so the surface is fully at its final visual state with no in-flight transition. The not-reduced branch runs the tween exactly as before.

**4. How its test exercises reduce-motion (the override mechanism you MUST reuse):**
`DisagreementPointsRail.test.tsx` passes the **`reduceMotionOverride` boolean prop** (e.g. `reduceMotionOverride` at :84, :96, :103…) so the hook returns `true` in precedence and the component renders in its snapped state (the row testID is present immediately). `a11y693ReduceMotionPrimitive.test.tsx` additionally (a) unit-tests the hook's OS path with `jest.spyOn(AccessibilityInfo, 'isReduceMotionEnabled').mockResolvedValue(...)` + `addEventListener` mock (:41-49), and (b) source-scans the adoption: imports the hook, `useReduceMotion(reduceMotionOverride)` present, and `not.toMatch(/AccessibilityInfo/)` / `not.toMatch(/reduceMotionChanged/)` (:182-198 — the **dedupe proof**). This card's tests mirror both: the `reduceMotionOverride`/`reduceMotion` prop for render-parity, and the dedupe source-scan for the swap.
